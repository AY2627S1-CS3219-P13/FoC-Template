# Repository guidance

Friend on Campus (FoC) is a microservice project: one service per top-level
folder, a Next.js frontend and a shared Nginx gateway. Each service has its own
`AGENTS.md` with service-specific rules — read it before touching that folder.

## Container-first

All tooling comes from containers. Do not install Go, Node or system packages on
the host; use the Compose services below, which pin the same versions CI uses.

## Running locally

```sh
sh user-service/scripts/init-env.sh
sh credit-service/scripts/init-env.sh
docker compose up --build -d gateway
```

The gateway owns `http://localhost:3000` and starts the frontend, User, Supplier
and Credit services. Direct development ports are User 8080, Credit 8082 and
Supplier 8083; Mailpit is on 8025. Internal ports (8081) stay on the Compose
network and are rejected by the gateway.

## Checks

Run the checks for every area you touched, and the smoke test for anything that
changes wiring (Compose, gateway, Dockerfiles, environment variables).

```sh
docker compose --profile test run --build --rm user-tests       # gofmt, vet, go test -race, build
docker compose --profile test run --build --rm supplier-tests
docker compose --profile test run --build --rm credit-tests
docker compose --profile test run --build --rm frontend-checks  # eslint, tsc --noEmit, next build
sh scripts/smoke.sh                                             # live end-to-end through the gateway
```

Formatting is enforced, not suggested. To reformat a Go service in a container:

```sh
docker compose --profile test run --rm --no-deps -v ./user-service:/app user-tests gofmt -w cmd internal
```

The same commands run in GitHub Actions (`.github/workflows/ci.yml`), so a green
local run is a green CI run.

## Service boundaries

- User Service owns credentials, sessions and roles. No other service stores
  passwords, reads User's database or caches authentication results; they
  validate each request through User's internal endpoint.
- Each service owns its own PostgreSQL database and its own numbered, embedded
  migrations. Add migrations; never edit an applied one.
- Credits move only through Credit Service escrows; balances are never written
  directly.
- Cross-service calls are internal HTTP with a bearer token, never shared
  database access.

## Conventions

- Go handlers are `func(http.ResponseWriter, *http.Request) error` wrapped by the
  service's endpoint helper, and every error response is
  `{"error":{"code","message"}}`.
- Configuration is read and validated at startup; the process must refuse to
  start on invalid configuration rather than degrade at request time.
- SQL values are always parameters. Identifiers that vary (sort columns) come
  from an allowlist.
- Secret material — passwords, session tokens, verification codes, internal
  tokens — is never logged, returned in an error, or committed. `.env` files are
  generated by the `init-env.sh` scripts and stay untracked.
- Containers run as a non-root user with a read-only filesystem and
  `cap_drop: [ALL]`; keep new services that way.

## Changes

- Keep diffs small and in the existing style; update the affected `README.md` /
  `API.md` in the same change.
- Do not weaken a test to make it pass.
